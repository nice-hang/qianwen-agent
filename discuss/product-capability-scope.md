# 千问类 Chatbox 用户视角产品能力范围

本文记录从用户视角讨论出的第一版产品能力范围。目标是先明确用户能感知到的能力，再倒推 Agent、Server 和 UI 的实现。

## 1. 产品定位

第一版不追求“能力大全”，而是做成一个支持多轮聊天、深度思考、图片理解、联网搜索和轻量记忆的千问类 Chatbox。

用户不感知 AgentLoop、ToolRegistry、ContextBuilder 等技术概念，只感知：

- 能不能自然聊天。
- 能不能多轮追问。
- 能不能上传图片并理解。
- 能不能在需要时查最新资料。
- 能不能展示可信的思考/搜索过程。
- 能不能记住稳定偏好和项目背景。

## 2. P0 核心体验

这些是 Chatbox 的最低可用体验。

| 用户功能 | 用户看到什么 | 可行性 | 备注 |
| --- | --- | --- | --- |
| 普通聊天 | 输入问题，流式回答 | 高 | 最基础链路 |
| 多轮追问 | 能基于上下文继续问 | 高 | Server 存完整 messages，Agent 注入部分上下文 |
| 停止生成 | 回答中可以停止 | 高 | 流式链路要支持 abort |
| 重新生成 | 对同一问题重新回答 | 高 | 需要保留原始 user message |
| 会话列表 | 新建、切换历史会话 | 高 | 第一版可先做单用户 |
| Markdown 渲染 | 标题、列表、代码块 | 高 | Web/RN 都需要支持 |
| 深度思考开关 | 用户可选择快速回答/深度思考 | 中 | 后端调整 reasoning、max steps、工具策略 |
| 深度思考过程展示 | 显示正在分析/正在搜索/正在整理 | 中 | 展示后端整理后的事件，不展示完整工具链 |

## 3. P0.5 亮点能力

这些能力让产品明显不像普通聊天壳。

| 用户功能 | 用户看到什么 | 可行性 | 备注 |
| --- | --- | --- | --- |
| 图片上传问答 | 传截图/图片，问“这是什么/哪里有问题” | 中-高 | 需要接多模态模型 |
| 截图分析 | 上传页面截图，让 AI 分析 UI/内容/错误 | 中-高 | 很适合作为主演示场景 |
| OCR/表格提取 | 从图片里提取文字、金额、表格 | 中 | 依赖视觉模型能力 |
| 联网搜索 | 问最新信息，显示参考了 N 条结果 | 中 | 可先接搜索 API 或 mock search |
| 来源展示 | 回答里展示引用来源 | 中 | 搜索结果需要结构化返回 |
| 工具过程提示 | 正在搜索、找到 N 条信息 | 中 | 由事件协议支撑 |

图片理解优先级高于 RAG。它用户感知强，技术链路也贴近主流 Chatbox。

## 4. P1 可后续增强

这些有价值，但不建议第一阶段做重。

| 用户功能 | 用户看到什么 | 可行性 | 备注 |
| --- | --- | --- | --- |
| 记忆偏好 | “记住我在做千问 demo” | 中 | 需要记忆提取和注入 |
| 记忆管理 | 用户能查看/删除已记住内容 | 中 | 比偷偷记忆更产品化 |
| 待办/计划生成 | 帮用户拆实现计划并生成任务 | 高 | 可先存 DB |
| 创建待办确认 | 创建前让用户确认 | 中 | 体现 Agent 安全边界 |
| 小文件总结 | 上传短 txt/md 后总结 | 中 | 不做 RAG 也可直接注入上下文 |
| 模型/模式设置 | 快速/深度/联网/图片增强 | 高 | 第一版可做简单开关 |

小文件总结可以作为“轻文件能力”，但完整 RAG 暂缓。

## 5. P2 暂不实现

| 功能 | 暂不实现原因 |
| --- | --- |
| 完整 RAG 知识库 | 成本高，当前不是主线 |
| Skill 系统 | 面向开发者生态，不是 C 端核心体验 |
| MCP 接入 | 云端内置工具场景不需要开放协议 |
| Subagent | 用户无感，复杂度高 |
| LangGraph 工作流编辑 | 偏开发平台，不是 Chatbox |
| 语音/TTS | 体验不错，但不是架构核心 |
| 生图/视频 | 会稀释主线 |
| 完整账号体系 | 第一版可先做单用户或 mock auth |
| 插件市场 | 与当前产品形态不匹配 |

## 6. 第一版用户功能范围

第一版实现范围建议固定为：

```txt
1. 聊天
   - 新建会话
   - 历史会话
   - 流式回答
   - 停止生成
   - 重新生成
   - Markdown 渲染

2. 深度思考
   - 快速/深度模式切换
   - 思考过程面板
   - 展示关键过程事件

3. 图片理解
   - 上传图片
   - 图片预览
   - 图文混合提问
   - 截图分析/OCR 类回答

4. 联网搜索
   - 模型决定是否搜索
   - 搜索过程提示
   - 来源数量和来源列表

5. 轻量记忆
   - 记住项目背景/用户偏好
   - 展示已记住内容
   - 支持删除记忆
```

## 7. 推荐用户路径

推荐用连续场景验证产品，而不是菜单式展示：

```txt
用户：我在做一个千问类 Chatbox，帮我规划功能
AI：流式回答，给出功能分层

用户：开启深度思考，问“现在主流 Chatbox 是不是 agent loop”
AI：显示正在搜索，参考了 N 条结果，输出结论

用户：上传一张产品截图
AI：分析截图内容，指出可优化点

用户：让它记住“我使用 RN + React，RAG 暂缓”
AI：写入记忆

用户：新开会话问“继续我的千问 demo”
AI：基于记忆恢复背景
```

## 8. 当前结论

产品能力上，第一版范围已经收敛：

> 做一个支持多轮聊天、深度思考、图片理解、联网搜索和轻量记忆的千问类 Chatbox。暂不做 RAG、Skill、MCP、Subagent、LangGraph 工作流、生图和完整账号体系。

后续讨论顺序：

1. Agent 技术实现。
2. Server 技术实现。
3. 前端技术实现。
